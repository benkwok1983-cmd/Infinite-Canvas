## 一、最终优化需求与工作目标

### 需求 1：Codex 订阅额度接入 GPT Image 2.5

- **核心诉求**：像画布现有 gpt-image-2 一样，用 ChatGPT 订阅额度（本机 codex 登录态）使用 Image 2.5 生图；**只走订阅额度，不接 API 计费**（用户明确澄清：这是指 2.5 通道的计费边界，不是要删掉原有 API 回退机制——回退改为 UI 开关控制，默认关）。
- **背景约束**：此前用户尝试接入 2.5 失败。调查确认根因：Codex 通道的 `--model` 参数是宿主代理模型而非图像模型；图像模型由服务端决定；`gpt-image-*` 字符串在进 CLI 前就被过滤。

### 需求 2：画布接入 Skill 体系

- **核心诉求**（用户逐步澄清后的最终形态）：
  1. 把 GitHub 开源 skill 或自建 skill **导入画布的 Skill 库**；
  2. 画布上添加**「生图 Skill」节点**，节点上**下拉选择 skill**；
  3. 与"参考图 + 提示词"组合，**连线到 API 生成 / ModelScope 生成节点**生图，产出指定风格图像；
  4. **样式样板**：同一 skill 内的多种风格（如不同墨色/纹理/配方）做成节点上的二级下拉，导入的 GitHub skill 能**自动识别**样板；
  5. **提示词是可选项而非必要条件**：参考图 + Skill + 生成节点即可生图。

### 工作方式要求（用户提出，全程遵守）

1. 先出 PRD 作为工作基础，对照详细计划表执行；
2. 做好代码审查（每阶段独立审查 + 问题修复闭环）；
3. 每阶段收尾写进度日志与 handoff 接手文件；
4. 消耗生图/LLM 额度的验证必须先获用户授权；非 Codex 通道测试用 ModelScope 免费模型；
5. **隔离纪律**：所有修改只在 `C:\agent-workspace\zcode\Infinite-Canvas`（zcode/iteration-01 分支），`C:\Infinite-Canvas` 原始基准绝不修改。

## 二、工作内容、思路与操作方案

### 总体思路

两条需求共用一个设计原则：**新能力全部增量叠加，不破坏现有链路**。具体表现为：不选新功能时请求与基线逐字段一致（有单测锁定）；每阶段经独立代码审查、问题清零后收尾；耗额度的验证全部推迟到用户授权后集中执行。

### Phase 1：Codex 2.5 可行性调查与探测工具（不花额度先行）

- 调查确认：Codex 生图走 `gpt-image-2-skill` helper（ChatGPT 后端 `codex/responses` + `image_generation` 工具）；上游 20 次对照实验记录证实"2.5 请求被接受但服务端总返回别名"，以及 size/background 等参数陷阱。
- 产出独立探测脚本 `tools/zcode-verify/codex_image25_probe.py`（默认 dry-run 零额度，`--run` 才真实调用），用于额度恢复后做三变体对照验证。

### Phase 2：Codex 订阅实验性 2.5（实现）

- **后端**：请求模型新增 `image_model` 字段全链路穿线；实验档（flare/sunburst）走 `request create --body-file` 注入 `tools[].model`；`parse_codex_observed_image_model` 从 SSE 事件解析服务端实际路由（只采信 `response.completed`，防 `created` 回显虚报）；诚实反馈元数据（请求模型/观察模型/确认标志/实际尺寸）经 `build_online_image_result` 透传到前端。
- **API 回退（经用户澄清修订）**：auto 档的 Codex→OpenAI 回退恢复，由 provider 级 UI 开关 `allow_api_fallback` 控制（API 设置页 Codex 卡片 toggle，默认关）；**2.5 实验档严格只走订阅，任何情况不回退**；无回退可用时 401 直报"请重新登录"。
- **前端**：两个画布的 Codex 模型下拉自动出现三档（gpt-image-2 / flare / sunburst），实验档带"实验"标识；生成请求携带 `image_model`；未确认时 toast 提示。

### Phase 3：Skill 库后端

- **存储规范**：`skills/custom/<id>/SKILL.md` + `.skill_meta.json`（来源/repo/commit SHA 随目录走）。
- **三来源扫描**：custom（可管理）/ builtin（仓库 skills/ 只读）/ codex（`~/.codex/skills` 只读），`realpath+commonpath` 三重路径穿越防护。
- **GitHub 导入（确认制）**：preview（拉 zipball→元数据预览，不落盘）→ install（固定 commit SHA）；**monorepo subdir 支持**；zip 导入；check-update（轻量 commits API）/ upgrade（隐藏备份目录 + 失败回滚）。
- **安全**（独立审查实测确认）：zip-slip 四重防护、单文件/总量/数量限额、YAML 别名炸弹防护、第三方脚本永不执行只标记警告、大文件自动跳过（>2MB 非正文文件）。

### Phase 4：Skill 库管理页

- 新页面 `skill-manager.html`（接入主导航）：三分组列表、GitHub 导入向导（预览确认 → 固定 SHA 安装 → 409 覆盖勾选）、zip 上传、自建编辑器、检查更新/升级弹层。

### Phase 5：画布「生图 Skill 节点」

- **节点**：普通画布新节点类型，skill 下拉（我的/内置分组）+ 样板二级下拉 + 快速/智能模式分段开关 + 智能模式 LLM 模型选择下拉；连线闸门（canConnect/canOutput/createNodeByType/右键菜单）全链路打通，每个生成节点限接一个 Skill。
- **编译注入双通道**：API 生成节点走 `payload.skill` 由后端统一编译（覆盖全部 provider）；ModelScope 节点走前端预编译（专用端点）。**快速模式**=确定性拼接（skill 指令+样板+用户需求，总长受 3800 上限控制适配上游 prompt≤4000 限制）；**智能模式**=LLM 融合改写（默认 codex 聊天通道，结果按"skill 内容快照+模式+provider+model+prompt"哈希缓存，LRU 200 落盘，asyncio.Lock 按 key 串行防重复消耗）。
- **交互**：生成节点显示"✨ skill 名 · 模式"行与「预览提示词」按钮；编译期间"AI 编译中"徽标 + 生成按钮锁定防重复；转圈卡片先于编译创建（点击 133ms 内出现）；编译失败回收卡片+落日志。
- **溯源**：生成日志记录 skill id/版本/内容 SHA/样板/编译后最终提示词。

### 追加迭代（用户使用中提出）

- **样式样板（variants）**：SKILL.md frontmatter `variants: [{id,label,prompt}]` 约定；管理页样板编辑器（含 **AI 识别样板**——LLM 分析 SKILL.md 自动提取可枚举风格变体，已实测 mono-color 识别 12 个）；mono-color 预置 15 个样板（8 单墨 + 6 双墨配方 + 照片网点版画）。
- **提示词可选化**：ModelScope 节点有参考图即可生图（原强制要求提示词）。

### Phase 6：额度验收（额度恢复后执行）

- **T1.2 三变体探测**（3 次订阅生图）：auto/flare/sunburst 全部返回别名 `gpt-image-2-codex` → 服务端接受 2.5 请求但未确认切换，**维持"实验性"标注**，诚实反馈设计按预期工作。
- **Codex 订阅 smoke**：画布端 42 秒出图成功。
- **智能模式验证**：LLM 融合改写 662 字提示词（样板+风格规则融合），缓存命中正常。
- **AI 识别样板**：真实调用成功（12 个样板，中文名+英文指令）。

### 验收过程中实测发现并修复的问题（7 个）

1. codex 通道尺寸映射：服务端只接受 `1K` 与精确宽高，`auto/2K/4K` 触发失败 → 收敛+精确像素 snap；
2. 提示词经 .cmd 垫片时**换行被 cmd.exe 重新切分**导致参数丢失（画布多段提示词必现）→ 折叠单行；
3. fast 拼接超上游 prompt≤4000 上限 → 3800 总长控制；
4. 画布右键菜单漏了 Skill 入口 → 补齐；
5. 子页面 HTML 被浏览器启发式缓存（用户刷新拿不到新版）→ 服务端 no-cache + 画布列表链接动态版本参数；
6. 智能模式点击生成后长时间无反馈（编译阻塞卡片创建）→ 卡片前置 + "AI 编译中"徽标 + 按钮锁定防重复生图；
7. Skill 库缓存不随管理页改动更新 → 60 秒 TTL 自动刷新。
